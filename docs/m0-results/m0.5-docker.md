## Non-root settings
- Both images create group and user `coroner` with UID/GID 10001, no home, shell `/usr/sbin/nologin`, then `USER 10001:10001`.
- Compose sets `user: "10001:10001"`, `cap_drop: [ALL]`, `security_opt: ["no-new-privileges:true"]` on both services.

## Volume design
- Named volume `coroner_evidence` (project `coroner`, so the Docker name is `coroner_coroner_evidence`), mounted at `/data/evidence` in the Collector only. No bind mounts.
- The Collector image bakes `/data/evidence` as `10001:10001`, mode 0750. A fresh named volume inherits that ownership on first mount. `/data` stays root-owned.
- The Demo_App image has no evidence directory and mounts no volume.
- The existing spike volume `coroner-spike_coroner_spike_evidence` is not referenced.

## Healthchecks
- Collector: python one-liner requests `http://127.0.0.1:8081/healthz`. Healthy only on HTTP 200 and JSON `storage_ok is true`. interval 2s, timeout 3s, retries 25, start_period 5s.
- Demo_App: python one-liner requests `http://127.0.0.1:8080/health`, healthy on HTTP 200. interval 2s, timeout 3s, retries 10.
- Demo_App `depends_on` the Collector with `condition: service_healthy`.
- Restart policy: Collector `on-failure:5`, Demo_App `"no"`.

## Memory limits
Demo_App: `mem_limit` and `memswap_limit` both `${CORONER_DEMO_MEM_LIMIT:-128m}` (no swap, so the kernel OOM-kills). The Collector has no memory limit.

## Network exposure
Ports bind to loopback only: `127.0.0.1:${CORONER_COLLECTOR_PORT:-8081}:8081` and `127.0.0.1:${CORONER_DEMO_PORT:-8080}:8080`. The Demo_App reaches the Collector at `http://collector:8081` on the default Compose network. `CORONER_ENABLE_DESTRUCTIVE_ENDPOINTS` defaults to `0`.

## CMD deviation
The spec text suggests `uvicorn ... --workers 1`. The images use `CMD ["python", "-m", "coroner.<service>.main"]` instead. `main()` in each module builds its config and app from the environment and runs uvicorn in-process with a single worker. Neither module exposes a module-level `app` or a zero-argument factory, so `uvicorn module:app` would need production code changes, which were out of scope. The static test `test_negative_module_cmd_requires_single_worker_source` checks that the module's source sets a single worker.

It then applies single mutations that must each fail the matching check, through `test_negative_compose` and `test_negative_dockerfile`. Real-file tests then run the same checks against the actual files, including a check for no `latest` or untagged images.
