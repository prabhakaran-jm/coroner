## Interfaces
- `DockerPort` matches the design signatures exactly. `DockerCli(*, run, base_env, docker_exe, timeout_s, compose_up_timeout_s, clock)`. Every call is `run(argv_list, env=build_child_env(base, overrides), capture_output=True, timeout=..., check=False)`. `compose_up` builds `[exe, compose, -p, coroner, up, -d, [--no-deps], [--force-recreate], <service>]`. `container_id` runs `compose -p coroner ps -a -q <service>` and requires 64 lowercase hex. `inspect` returns `InspectResult(raw: bytes, parsed, inspect_time: datetime UTC)`. `kill` runs `kill --signal <SIG> <id>`.
- `InspectResult` is named in the design (`raw bytes + parsed JSON + inspect_time`) without field names. The chosen names are `raw`, `parsed`, `inspect_time`.
- `evaluate.ContainerState(exit_code, oom_killed, status)`; `Evaluation(passed, message, checks)`; `Check(name, passed, detail)`. `Check` matches the manifest `checks` entries (`name`, `passed`, optional `detail`).
- `manifest`: `RunManifest`, `Expected`, `Failure`, `EvidenceRef`, `ContainerState` (manifest block), `InspectExcerpt`, `generate_run_id`, `write_manifest`, `read_manifest`, `save_raw_inspect`, `extract_inspect_excerpt`.
- `collector_client`: `CollectorClient(base_url, transport=, wall_clock=, timeout_s=)` with `health()`, `get_evidence(run_id)`, `post_termination(run_id, payload)`. `check_ready(client, clock, sleep, window_s=60, poll_s=1)` returns `ReadinessOutcome(status, message, exit_code, health, attempts, waited_s)`.
- Import boundary: the runner imports only `coroner.common` (`envparse`, `timeutil`) and `coroner.evidence.schema` (`RUN_ID_RE`). This is the `runner -> {evidence, common}` rule in `tests/unit/test_structure.py`.

| b | `ContainerState` exists in `evaluate` and in `manifest` | Not a conflict inside one module. The design does not name the manifest `container_state` block class, so `manifest.ContainerState` is a worker choice. | Not renamed (no design text requires it). Owner: `evaluate.py` is task 6.3/6.5 owner; `manifest.py` is task 6.9/6.13 owner. |
| c | Experiment identifier case | Design: manifest `"experiment": "C"` (uppercase), run id `c-2025...` (lowercase), `expected` per A/B/C. `evaluate` uses uppercase `A`/`B`/`C` and rejects other values with `ValueError`; `generate_run_id` lowercases its input. Both agree with the design. | No change. Callers pass uppercase to `evaluate_*` and to the manifest `experiment` field; `generate_run_id("C")` yields the lowercase prefix. |
| d | Readiness names and exit codes | Failure codes `collector_unhealthy` and `collector_storage_unhealthy` and the message "Collector storage is not healthy" match design preamble step 3. Both failures give exit code 1 and `demo_app_may_start == False`. 200 with `storage_ok` false, absent, null, `1`, or `"true"` aborts at once. Corrected contract: an HTTP 200 whose body is invalid JSON, empty, non-object JSON, or has `storage_ok` not exactly `true` aborts immediately as `collector_storage_unhealthy` ("Collector storage is not healthy"), with `attempts == 1` and no retry. Only a non-200 status (for example 503) and connectivity failures (no response, timeout) retry, up to 60 s. The earlier note that unusable 200 bodies were retried for 60 s is withdrawn. | Code and `test_prop_readiness.py` were corrected before this checkpoint. No further change. The CLI maps failure to its exit code (design: 1 failed/aborted, 2 environment) in task 6.14 or later. |

Independent check: host window 12:00:00.000 to 12:00:00.020, server time 12:00:00.013 gives offset +3, uncertainty 10 ms, round trip 20 ms. A container timestamp 12:00:09.253 minus 3 ms is 12:00:09.250, the host time. This matches the design rule `ts - clock_offset_ms`. The 250 ms tolerance is not in this module. | No change. |

## Cross-platform notes
- Manifests and raw inspect files are written in binary mode with `\n`, through a temp file in the same directory, `os.fsync`, and `os.replace`. Stored paths use `as_posix()`; a Windows-style string is converted with `PureWindowsPath`.
- The default `urllib` transport uses an opener with no proxy handler, because the Collector is on loopback.
- No `fcntl`, shell, or POSIX tool is used. Waits use injected `sleep`; the readiness window uses the injected monotonic clock.
