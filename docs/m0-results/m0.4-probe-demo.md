Results notes for milestone M0.4. Only observed results are recorded.

## Task 4.1 Probe config and real readers

Files: `coroner/probe/probe.py`, `coroner/probe/__init__.py`, `tests/unit/probe/test_probe_config_readers.py` (plus an empty `tests/unit/probe/__init__.py`). Task 4.4 owns `test_probe_units.py`, which was not created.

### Contracts

- `ProbeConfig(run_id, collector_url, interval_ms, send_timeout_s=0.200, start_deadline_s=0.100)`, frozen.
- `load_config(env, warn) -> ProbeConfig`. Reads only `env`, never mutates it, never reads `os.environ`.
- `read_rss_bytes(path="/proc/self/statm", page_size=<OS page size>) -> int`: statm field 2 times page size. Raises `OSError` (missing or unreadable) or `ValueError` (malformed). No `getrusage`, no fallback.
- `read_container_id(mountinfo_path, cgroup_path, env=None) -> tuple[str | None, str]`: `(id, source)` with source `mountinfo`, `cgroup`, `hostname`, or `none` (then id is `None`). The design signature is `tuple[str, str]`; `None` for the absent id is the documented null. Task 4.2 derives the null reason from `source == "none"` using `NO_CONTAINER_ID_REASON` ("no container id found in mountinfo, cgroup, or HOSTNAME", the design's example text).

### Decisions

- (a) The design is silent on an invalid explicit `CORONER_RUN_ID`. `load_config` raises `ValueError` naming the value. It never silently replaces it. Empty or missing generates `manual-<8 hex>` via `secrets.token_hex(4)`.
- (b) `CORONER_COLLECTOR_URL` is passed through unvalidated (default `http://collector:8081`).
- (c) Design Property 17 says any string other than an integer in 100..60000 gives 500 and one warning, so a supplied empty or blank value warns. Only an absent variable is silent. Accepted syntax is plain ASCII digits only: `+100`, ` 100`, `1.5`, `1e3`, `0x64`, and non-ASCII digits are invalid. This differs from the Collector's `parse_int_env`, which treats empty as the default and trims whitespace.
- (d) See the return type above.
- (e) mountinfo: `/containers/<64 lowercase hex>/`. cgroup: `/docker/<64 hex>` or `docker-<64 hex>.scope` (the design names no cgroup patterns; only these Docker forms are supported, so kubepods or cri-containerd layouts are not parsed). cgroup v2 `0::/` yields no id. `HOSTNAME` must be exactly 12 lowercase hex. Unreadable files fall through to the next source.
- The run id regex is copied from `coroner.evidence.schema.RUN_ID_RE` because the Probe may not import `coroner.evidence`. A test asserts the patterns are equal.

## Task 4.2
### Interface
`Probe(config, *, transport=None, rss_reader=read_rss_bytes, pid_reader=os.getpid, container_id_reader=read_container_id, monotonic=time.monotonic, wall_clock=<UTC now>, on_sample=None)`. Methods: `start(loop=None)` (idempotent), `async stop()`, `count_request()`, `build_sample(loop_delay_ms, loop_delay_reason=None)`, property `state` = `{"next_seq", "dropped"}`. `transport` is stored but unused until 4.3. `on_sample(sample)` is the non-blocking delivery seam for 4.3. The default wall clock is a local `datetime.now(timezone.utc)` because the Probe may not import `coroner.common`.
### Sample construction
Exactly the 11 schema fields plus `null_reasons` only when something is null. `seq` is taken and incremented under the lock as the last step, so a failed build never advances it. `ts` is the injected clock converted to UTC, truncated to milliseconds. `dropped` reads a counter that stays 0 until 4.3.
### Null reasons
- `rss_bytes`: `rss unavailable: <ExceptionName>` (no paths or messages), also used when the reader returns a non-integer, bool or negative value. Never 0.
- `container_id`: `NO_CONTAINER_ID_REASON` for `(None, "none")`; `container id unavailable: <ExceptionName>` if the reader raises. Source is then `none`.
- `loop_delay_ms`: the caller's reason (1 to 200 characters); `None` without a valid reason, or a negative, non-finite, bool or non-number delay, raises `ValueError`.
- `request_count` is never null.
### Decision: non-nullable failure
The design is silent. `pid` is non-nullable, so a failing or invalid `pid_reader` makes `build_sample` raise; the sampler skips that tick (no Sample, `seq` unchanged) and continues at the next deadline. An exception from `on_sample` is also contained.
### Schedule
`t0 = monotonic()` at task start; tick k is due at `t0 + k*interval`. The task sleeps until the deadline and re-checks after each wake (early wakes sleep again). Delay is `max(0, (now - deadline) * 1000)`. After a tick the next k is the smallest with `t0 + k*interval > now`, so missed deadlines are skipped with no burst and no drift. `monotonic` (default `time.monotonic`, the loop clock source) is used for deadlines; `ts` uses the separate wall clock.
### Lifecycle
`start` creates the task on the given or running loop. `stop` cancels and awaits it and is safe when not started or already stopped. No signal or atexit handlers, no thread, no HTTP, no flush.

## D36 note

Design decision D36 (approved, no schema change) records three rules: `pid` is non-nullable, so a failing or non-integer PID reading produces no Sample and does not advance `seq`; a timezone-naive wall clock is rejected (never read as local time), same handling; once `seq` is consumed, every failed handoff or delivery adds exactly one to `dropped`. Property 15 now says a failed non-nullable PID reading (or a naive clock) produces no Sample and substitutes nothing, and its nullable-measurement wording is kept ("for each failed nullable-measurement reader a null field with a reason"). Task 4.2 code was changed to reject naive datetimes.

## Task 4.3: sender, transport, dropped accounting

- **Interface.** `Probe.offer(sample)` serialises once (`json.dumps`, compact, `allow_nan=False`), calls the optional `on_sample` observer, then hands the body to the sender. `start()` starts the sampler task and one daemon thread named `coroner-probe-sender` (idempotent). `stop()` cancels the sampler, sets the exit event, and joins the thread for at most 0.5 s without blocking the event loop. Nothing is flushed; there is no atexit or signal handler.
- **Handoff.** One slot holding `(body, carried dropped, handoff time)`. `offer` under the lock: slot free means store and `Event.set()`; slot occupied (in flight or waiting) means the new Sample is discarded and `dropped += 1`. The slot stays occupied during the send, so an in-flight Sample is never replaced. No queue, no retry. `seq` stays consumed for discarded Samples.
- **HTTP transport** (default when `transport=None`): stdlib `http.client`, `POST {collector_url}/v1/samples`, `Content-Type: application/json`, `Content-Length`, body bytes unchanged. Only the `http` scheme is supported; other schemes, a missing host, an invalid port, connection errors and timeouts return False. Only status 200 is True (201/202/204, 3xx without following, 4xx and 5xx are False). The connection is always closed.
- **Deadline.** The sender computes `remaining = handoff + send_timeout_s - now` (monotonic), skips the send if it is not positive, passes `remaining` as `timeout_s`, and acknowledges only if the transport returned True and the clock is still within the deadline. The HTTP transport sets the connect timeout and the socket timeout before sending and before reading the response to the remaining budget, and rechecks between phases. **Limitation:** DNS resolution (`getaddrinfo`) is not interruptible by socket timeouts, so a stalled resolver can exceed 200 ms; the late result is never acknowledged, but the sender thread is busy until the call returns (new Samples are dropped meanwhile). The sampler is not affected.
- **Dropped accounting.** Starts at 0, saturates at 4,294,967,295. Every Sample carries the counter at construction. Failures (busy discard, transport False or exception, deadline exceeded, serialization failure, `on_sample` raising) add exactly one. An acknowledgement sets `dropped = max(0, dropped - carried)`, so drops that happened while the Sample was in flight are preserved (carried 5, two drops in flight, ack gives 2). All counter operations run under the Probe lock.
- **`on_sample` role.** Observer called with the built Sample after serialization and before handoff. If it raises, the Sample is dropped once and not offered; the loop continues. Returning normally is not an acknowledgement.
- **Delivery start.** The sender waits on an Event, so it starts at handoff; a test asserts the transport is entered within 100 ms. `offer` with a blocked transport stays under 10 ms in the test.

### Task 4.3 limitations (recorded at Checkpoint 9)

- DNS resolution (`getaddrinfo`) is not bounded by socket timeouts, so one delivery attempt can exceed the nominal 200 ms deadline.
- A late result is never acknowledged: the sender re-checks the monotonic deadline after the transport returns.
- A stalled resolver keeps the single sender thread busy until the call returns, so Samples produced meanwhile are dropped (counted in `dropped`).
- Real network behaviour has not been exercised: the HTTP transport is tested only against a recording `http.client.HTTPConnection` double; the default suite is network-free.
- The container `/proc` readers (`/proc/self/statm`, `/proc/self/mountinfo`, `/proc/self/cgroup`) have only been exercised with injected files on Windows, not inside a Linux container.
- The 300 non-blank-line Probe size limit is not yet automated (no size test exists; Task 4.9 owns Probe static and size tests). Current count: 298 of 300.
- The third-party Starlette/anyio `BlockingPortal` DeprecationWarning remains (1 warning in the full suite).
