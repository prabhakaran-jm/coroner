Default URLs when no `--collector-url` is given (`run` and `clock-check`), computed from the injected `env` mapping:

- Collector: `http://127.0.0.1:<CORONER_COLLECTOR_PORT or 8081>`
- Demo_App (`run` only): `http://127.0.0.1:<CORONER_DEMO_PORT or 8080>`

These are the two host-port variables that `compose.yaml` already uses. A port value that is not 1..65535 in ASCII

## 3. Module API for dependency injection

Files and owners (section 8): `coroner/runner/cli.py`, `coroner/runner/__main__.py`, `coroner/runner/summary.py`.

```python
# coroner/runner/cli.py
def main(
    argv: Sequence[str] | None = None,        # None -> sys.argv[1:]
    *,
    docker: DockerPort | None = None,         # None -> DockerCli() (built lazily, after validation)
    collector: CollectorClient | None = None, # None -> CollectorClient(<collector url>, transport=http, wall_clock=wall_clock)
    http: Transport | None = None,            # forwarded to ExperimentContext.http and to the default CollectorClient
    wall_clock: Callable[[], datetime] | None = None,
    monotonic: Callable[[], float] | None = None,
    sleep: Callable[[float], None] | None = None,
    out: TextIO | None = None,                # None -> sys.stdout
    err: TextIO | None = None,                # None -> sys.stderr
    env: Mapping[str, str] | None = None,     # None -> os.environ; read ONLY for CORONER_COLLECTOR_PORT / CORONER_DEMO_PORT
) -> int

# coroner/runner/__main__.py
import sys
from coroner.runner.cli import main
if __name__ == "__main__":
    sys.exit(main())
```

Rules for `main`:

- Returns an int in {0, 1, 2}; never calls `sys.exit` itself. `argparse` is built with `exit_on_error=False` or the
  `SystemExit` it raises is caught and converted: `SystemExit(code)` from argparse becomes `return code` (2 for an
  error, 0 for `--help`). All argparse output goes to the injected `out`/`err` (use `parser.error` override or
  redirect), never to the real `sys.stderr` when `err` is injected.
- When a parameter is `None`, the real default is used; the `ExperimentContext` constructor receives only the
  injected callables that are not `None` (so the dataclass defaults still apply).
- `out` and `err` are text streams; every line is written with a trailing `\n` (LF). Output is ASCII only.
- Importing `coroner.runner.cli` or `summary` must not touch the network, Docker, or the filesystem.
- `summary` and argument-error paths must never construct `DockerCli`, `CollectorClient`, or call `docker.available()`.
  `clock-check` constructs only a `CollectorClient`.
- An unexpected exception inside `summary` or `clock-check` is not swallowed silently: print
  `error: <ExcType>: <message>` to `err` and return 2.

### run

1. Parse argv (lower-case experiment). Argparse errors -> exit 2.
2. Pre-validate, in this order, before any Docker operation, any file creation, any run id, any manifest:
   a. `--mem-limit`: `parse_mem_size(args.mem_limit)`. `ConfigError` -> `err`: `error: invalid --mem-limit: <ConfigError message>`,
      return 2. A parsed value of `0` is also rejected: `error: invalid --mem-limit '0' (must be greater than zero)`,
      return 2 (N6).
   b. `--leak-chunk-bytes` outside 1..104857600 -> `err`: `error: invalid --leak-chunk-bytes <N> (expected 1 to 104857600)`, return 2.
   c. `CORONER_COLLECTOR_PORT` / `CORONER_DEMO_PORT` when present and invalid -> `err`, return 2.
3. Build the context (no Docker call yet):

```python
kwargs = {k: v for k, v in {"http": http, "wall_clock": wall_clock, "monotonic": monotonic, "sleep": sleep}.items() if v is not None}
docker_port = docker if docker is not None else DockerCli()
collector_client = collector if collector is not None else CollectorClient(
    collector_url, transport=http, wall_clock=wall_clock)           # None values are accepted by CollectorClient
ctx = ExperimentContext(
    experiment=args.experiment,            # lower case "a"/"b"/"c" is fine: __post_init__ upper-cases it (N1)
    docker=docker_port, collector=collector_client,
    runs_dir=args.runs_dir, mem_limit=args.mem_limit, leak_chunk_bytes=args.leak_chunk_bytes,
    demo_url=demo_url, **kwargs)
result = {"a": exp_a.run, "b": exp_b.run, "c": exp_c.run}[args.experiment](ctx)
```

   `ExperimentContext` accepts lower case: its validation is `experiment.upper() in EXPECTED_STATE` and it then stores
   the upper-case letter, so `manifest.experiment`, `result.experiment` and evaluator calls are upper case, while the
   run id prefix is lower case. The CLI never upper-cases or lower-cases anything itself.
   `sample_interval_ms` and `rand_hex` are not exposed (left to the defaults).
4. Docker-unavailable is NOT checked by the CLI. It stays in the preamble: with an unavailable Docker the experiment
   returns `ExperimentResult(exit_code=2, outcome="not_started", run_id=None, manifest_path=None,
   message="Docker is unavailable")`; the CLI prints and returns that exit code unchanged. No run id, no manifest.
   (If an injected `docker.available()` raises, the preamble also maps it to the same exit 2.)
5. Output: let `rc = result.exit_code`.
   - `result.outcome == "not_started"`: `err.write(result.line + "\n")`.
   - otherwise: `out.write(result.line + "\n")`, then if `result.manifest_path is not None`
     `out.write("Manifest: " + posix_path(result.manifest_path) + "\n")`; then, if `result.failure is not None`,
     `out.write(f"Failure: {failure.code}: {failure.message}\n")` (only for outcomes failed/aborted).
   - Return `result.exit_code` exactly (0 passed; 1 failed or aborted; 2 for `not_started` and for
     `docker_compose_failed`).
6. `KeyboardInterrupt` from the experiment (it re-raises after writing an `interrupted` manifest): print
   `Interrupted. The run manifest was marked aborted.` to `err` and return 1.

### summary

```python

    ...

@dataclass(frozen=True)

    malformed_lines: tuple[tuple[int, int, str], ...]     # (line_no, byte_length, kind), at most 5, file order
    last_sample_time: str                    # "none received" when there is no sample
    termination_cause: str                   # "unknown" when no termination record
    unobserved_interval_note: str | None
    container_status: str | None             # None when manifest.container_state is None
    container_exit_code: int | None
    container_oom_killed: bool | None
    container_inspect_time: str | None
    container_left_running: bool
    durability_level: str                    # manifest.durability_level
    sample_timing: Mapping[str, Any] | None  # manifest extra["sample_timing"]; used only when experiment == "B"
    diagnostics: Mapping[str, Any] | None    # manifest extra["diagnostics"]; used only when experiment == "C"
    sampling_limitations: Mapping[str, Any] | None   # manifest extra["sampling_limitations"]; only when experiment == "C"
    warnings: tuple[str, ...]

def build_summary(runs_dir: Path | str, run_id: str) -> Summary      # raises SummaryError only
def render_summary(summary: Summary) -> str                          # pure; ASCII; LF; ends with "\n"
def summary_exit_code(summary: Summary) -> int                       # always 0 (EXIT_PASSED); see below
```

`build_summary` (read-only; the only filesystem calls allowed are `open`/`read` of existing files and `Path.exists`):

1. `validate_run_id_for_path(run_id)`; `RunIdError` -> `SummaryError(f"invalid run id {run_id!r}: ...")`. No path is built from an invalid id.
2. `manifest_path(runs_dir, run_id)`; `read_manifest(path)`:
   - `FileNotFoundError` (or the run directory/runs directory missing) -> `SummaryError(f"run {run_id} not found under {runs_dir}")`
   - other `OSError` -> `SummaryError(f"cannot read manifest {path}: {exc}")`
   - `ManifestError` -> `SummaryError(f"manifest {path} is not valid: {exc}")`
   - `manifest.run_id != run_id` -> `SummaryError("manifest ... belongs to run X, not Y")`.
3. Evidence: the file is `<runs_dir>/<run_id>/evidence.jsonl` (the stored `evidence.host_copy_path` is relative to the
   directory the run was started from, so it is NOT used to locate the file; it is only reported in a warning if the
   stored `record_count` differs, see below).
   - `manifest.evidence is None` or the file does not exist -> `SummaryError(f"no evidence copy for run {run_id} (manifest outcome {outcome}[, failure {code}])")` (N3).
   - `OSError` on read -> `SummaryError`.
   - `result = read_evidence(path, name=f"{run_id}.jsonl")`; `summarize(result)`.
   - Unparseable evidence: `result.records` is empty AND `result.errors` is non-empty -> `SummaryError("evidence copy for run X has no valid record (N malformed lines)")`.
     A file with some valid records and some malformed lines is NOT an error: it exits 0 and reports the malformed count.
     A zero-byte file (no records, no errors) is NOT an error: sample count 0, `last_sample_time` "none received".
4. Warnings (never change the exit code; shown as `Warning: ...` lines): stored `evidence.record_count` differs from
   `len(result.records)`; `summary.durability_levels` contains a level different from `manifest.durability_level`;
   every string in `RunSummary.warnings`.
5. `Summary` is filled only from stored values (section 4). No network, no Docker, no clock read, no write, no mkdir, no
   delete, no touch. The runs directory is not created when it does not exist.

`summary_exit_code` is 0 for any `Summary` that was built, whatever the stored outcome (`passed`, `failed`, `aborted`):
the design says `0 ok; 2 on missing/unparseable`. The `summary` command never returns 1. `main` returns 2 when
`build_summary` raised `SummaryError` (message to `err` as `error: <message>`, nothing on `out`).

### clock-check

```python
# lives in coroner/runner/cli.py
def run_clock_check(
    collector: CollectorClient,
    *,
    count: int,
    wall_clock: Callable[[], datetime],
    sleep: Callable[[float], None],
    out: TextIO,
) -> int
```

- Performs `count` sequential `collector.health()` calls (one measurement each), with `sleep(0.1)` BETWEEN
  measurements (not after the last). It does not use `check_ready` (no 60 s wait) and does not write anything.
- A measurement is "usable" only when `health.clock_offset is not None`. A response that is unusable (no response,
  non-200, bad `server_time`) is counted as failed and does not abort the loop. `storage_ok` is not required.
- Returns 0 when at least one measurement was usable. Returns 2 when none was usable, after writing the single line
  `error: no usable clock measurement from <url> (N attempts): <last error>` to `out` (frozen: this error line goes to
  `out`, not `err`; `main` adds nothing).
- `wall_clock` is used only to print `measured_at` (start of the first measurement) formatted with
  `coroner.common.timeutil.format_utc_ms`. The offset arithmetic comes from `CollectorClient`'s own clock (main passes the
  same injected `wall_clock` to both).

```text

Unreconciled:   0 probe-reported drops (uncertain: no)
Malformed:      0 lines quarantined (never counted as samples)
                line 12: invalid_json, 37 bytes                    # only when malformed_line_count > 0, at most 5 lines
Last sample:    2025-01-01T12:17:01.874Z
Termination:    <termination_cause>; <unobserved_interval_note>     # note part omitted when None
Durability:     crash (fsync before acknowledgement; storage caveats apply)

                anomaly beyond_tolerance: <ts>                      # one line per entry, B only
                anomaly after_container_stop: <ts>                  # one line per entry, B only

Limitations:    interval 500 ms; approx leak rate N bytes/s; <statement 1>; <statement 2>; <statement 3>                # C only

```

Formatting rules: booleans as `true`/`false`; `None` as `unknown`; `peak_rss_ratio_of_limit` with 2 decimals (`unknown`
when None); durability caveat text: `crash` -> `fsync before acknowledgement; storage caveats apply`, `process` ->
`no fsync before acknowledgement; evidence may be lost on a host crash`, any other value -> `storage caveats apply`.
`pre_kill` includes `late_received` (late-received is a subset). Counts for beyond_tolerance and after_container_stop are
`len(...)` of the stored lists. Experiment A wording (Requirement 9.12): the summary never prints the words "exception" or
"unhandled exception" for A; it prints the stored `termination_description` only if needed (it is not in the frozen format).
Nothing in the summary output depends on the current time or the current directory.

## 5. clock-check output (frozen)

```text
clock-check:    collector=http://127.0.0.1:8081
Measured at:    2025-01-01T12:00:00.000Z
Measurements:   20 of 20 usable
Offset:         +12 ms (positive = Collector clock ahead of host; host time = collector time - offset)
Uncertainty:    1.8 ms (half the round trip of the best measurement)
Offset median:  +12 ms
Offset range:   +10 ms to +14 ms (spread 4 ms)
Round trip:     min 3.6 ms, median 4.1 ms, max 9.9 ms
Tolerance:      250 ms (documented Experiment B clock tolerance; never changed automatically)
```

- `Offset` and `Uncertainty` come from the usable measurement with the smallest `round_trip_ms` (ties: the earliest).
  `Offset median` is `statistics.median_low` of the usable offsets (an int). Range is min and max of usable offsets;
  spread is max - min.
- The `Round trip:` median is `statistics.median` of the usable round trips. For an even count it is the mean of the two
  middle values (the contract was silent; the implementation and `test_cli_summary.py` pin this). It is not
  `median_low`, which applies only to `Offset median`.
- Signed offset is printed with an explicit `+` or `-` (`+0 ms` for zero); `uncertainty_ms` and round trips with one decimal.
- `Tolerance` prints `evaluate.CLOCK_TOLERANCE_MS` (the constant, 250). It is only displayed. The command never writes
  a tolerance, never edits a file, never changes the constant.
- If `abs(best offset) + best uncertainty > 250`, one extra line is printed: `Warning:        offset plus uncertainty exceeds the 250 ms tolerance; ask before changing the tolerance`. The exit code stays 0 (N7).
- Failed measurements add `Failures:` with the count and the last error text: `Failures:       3 (last: <error text>)` (only when > 0).
- No usable measurement: single line `error: no usable clock measurement from <url> (N attempts): <last error>` on `out`, return 2.

### Conflicts between the design and the code (none block implementation)

1. Design says `read_manifest` is used by run id; the code takes a file path (`read_manifest(path)`); use `manifest_path(runs_dir, run_id)` first.
2. Design `DockerPort` text matches the code; `EVIDENCE_COPY_NAME` and `MAX_LEAK_BYTES` exist in `base.py` but are not in its `__all__` (import them by name, or restate the constants in `cli.py`/`summary.py`).
3. Design says `--mem-limit` is pre-validated "before invoking Docker" (consistent). The code also validates it in `_validate_context`, but only AFTER `ExperimentContext` construction; the CLI must therefore validate first so no `DockerCli` or runs directory is created for a bad value.
4. `base._validate_context` accepts a zero memory limit (see N6) and the design does not say otherwise.
5. Design `RunSummary` is described as the Evidence_Reader output; the real dataclass is `coroner.evidence.reader.RunSummary` (not the CLI `Summary`). Do not confuse the two names; `cli`/`summary` import the reader's one as `RunSummary` and define `Summary` locally.
