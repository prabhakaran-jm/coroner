# M0.7 Runner Compose project isolation

## Why

`coroner/runner/docker_port.py` hardcoded `docker compose -p coroner`. Any experiment run through `python -m coroner.runner run ...` would therefore use the Compose project `coroner` and mount the M0.5 volume `coroner_coroner_evidence`. M0.7 evidence must live in its own volume, `coroner-m07_coroner_evidence`, so the Runner now accepts a project name.

## Behavior

| Item | Behavior |
|---|---|
| Default (variable unset) | Project `coroner`. Argv is identical to before (`docker compose -p coroner ...`). |
| `CORONER_COMPOSE_PROJECT=<name>` | Every `docker compose` call (`up`, `ps`) uses `-p <name>`. |
| Set but invalid or empty | Exit code 2, stderr `error: invalid CORONER_COMPOSE_PROJECT '<value>' (expected 1 to 63 lowercase letters, digits, hyphens or underscores, starting with a lowercase letter or digit ...)`. No Docker call, no run directory. There is no fallback to `coroner`. |
| Where it is read | Only `run`, in the same pre-validation block as `--mem-limit`, `--leak-chunk-bytes` and the port variables. `summary` and `clock-check` never read it. |
| Error precedence | `--mem-limit`, `--leak-chunk-bytes`, `CORONER_COLLECTOR_PORT`, `CORONER_DEMO_PORT`, `CORONER_COMPOSE_PROJECT`. First error wins. |
| Python API | `DockerCli(..., project="coroner")`, property `project`, `validate_compose_project(name)`, `DEFAULT_COMPOSE_PROJECT`. `DockerCli` validates before anything else. |

Valid project name: `^[a-z0-9][a-z0-9_-]*$`, at most 63 characters. Docker Compose documents the character rule but no length limit; the 63 cap is this Runner's own conservative choice (one DNS label).

Valid: `coroner`, `coroner-m07`, `coroner_m07`, `9lives`. Invalid: empty, `Coroner`, `-x`, `_x`, `a b`, `a.b`, `a/b`, `é`, 64 or more characters.

## Using it for M0.7

In the PowerShell session that runs the Runner:

```powershell
$env:CORONER_COMPOSE_PROJECT = 'coroner-m07'
python -m coroner.runner run a
```

Ports 8081 and 8080 must still be free, and the volume `coroner-m07_coroner_evidence` is the one the Collector will mount (it already exists from the clock-offset test, see `clock-offset.md`).

## Evidence-volume protection

- Compose resolves the Collector volume as `<project>_coroner_evidence`. With `-p coroner-m07 -f compose.yaml` this is `coroner-m07_coroner_evidence`, as observed live in `clock-offset.md` (project label `coroner-m07`, single mount `coroner-m07_coroner_evidence`, neither protected volume mounted). `-p` overrides `name: coroner` in `compose.yaml`.
- Throwaway no-Docker script `runs/m07_safety.py` printed all argv for `DockerCli(project='coroner-m07')` and for `cli.main` with `CORONER_COMPOSE_PROJECT=coroner-m07` (fake subprocess runner). All 5 compose argv start `docker compose -p coroner-m07`. No argv contains `coroner_coroner_evidence`, `coroner-spike_coroner_spike_evidence`, `-v`, `--volumes`, `down` or `prune`. The Runner never issues volume or `down` commands.

## Limitations

- Unit tests with fakes only. No live Docker verification of this change yet.
- The Runner still uses fixed host ports (8081, 8080, or the `CORONER_*_PORT` variables) and compose.yaml (unchanged, still `name: coroner`). It does not pass `-f`, so Compose reads `compose.yaml` from the working directory; run from the repository root.
- The Runner's `compose up` has no `--no-build`. If an image is missing, Compose may build it.
- The project name selects containers, network and volume together. Two projects cannot run at once because of the fixed ports.
