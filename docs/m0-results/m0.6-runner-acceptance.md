## 5. Decisions made during M0.6

- D1 (N3): `summary` exits 2 when the evidence copy is missing, and the message includes the manifest outcome and failure code so the cause stays visible. Unparseable evidence means no valid record plus at least one malformed line (exit 2). Partial malformation exits 0 and is counted. Empty file exits 0.
- D2 (N6): `--mem-limit 0` is rejected by the CLI with exit 2 before any Docker operation. `parse_mem_size("0")` still returns 0, and `base.py` is unchanged.
- D3: the initial manifest is written as `aborted` / `run_incomplete`, so an interrupted run never looks successful (`m0.6-runner-batch3.md`).
- D4: a surviving mutant in the CLI/summary mutation check (container exit code defaulting to `0` when no container state exists) is unreachable and was classified equivalent. Rendered output is identical (186 passed) and a stored container state cannot hold a `None` exit code (`m0.6-runner-cli.md` lines 649 and 661, 699-701).
